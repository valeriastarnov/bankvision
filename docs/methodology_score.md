# Индекс полноты и согласованности данных и маршрутизация

> Индекс — **правило-ориентированный балл 0–100**. Это **не вероятность** и **не
> откалиброванная уверенность**. **Веса выбраны экспертно и не откалиброваны**: проверки
> на реальных заявках не было, данных для калибровки нет.

Реализация: `app/services/scoring.py`, `app/services/routing.py`. Параметры: `app/config.py`.

## Индекс

```
Индекс = Σ_k  w_k · s_k,     s_k ∈ [0, 1],   Σ w_k = 100
```

| Компонент k | Вес w_k | Оценка s_k |
|---|---|---|
| Качество фото | 20 | доля фото без флагов качества (размытость, темнота, пересвет, разрешение) |
| Полнота ключевых полей | 30 | доля ключевых полей (производитель, модель, заводской номер, год) с итоговым значением; поле, источники которого «расходятся» или «не подтверждено», не засчитывается — ни до, ни после выбора значения сотрудником |
| Согласованность источников | 30 | среднее по ключевым полям (таблица ниже) |
| Достаточность аналогов | 20 | 1.0 — диапазон по точной модели; 0.7 — по классу; 0.3 — аналоги есть, но меньше N; 0 — нет |

Оценка согласованности ключевого поля по статусу сверки (`crosscheck.py`):

| Статус | Балл |
|---|---|
| совпадает / совпадает после нормализации — на фото без флагов качества | 1.0 |
| совпадает, но только на фото с флагом качества | 0.5 |
| есть только в одном источнике | 0.25 |
| не подтверждено / расходится / нет ни в одном | 0 |

Статус «расходится» определяется по извлечённым значениям и не меняется после того, как
сотрудник выбрал итоговое значение. Выбор сотрудника индекс не повышает: ни согласованность,
ни полнота от него не меняются (исправлено 2026-10-27; до исправления выбор повышал полноту).

На экране заявки и в отчёте показывается вклад каждого компонента (`w_k · s_k`)
и основание (что именно учтено).

## Маршрутизация

Жёсткие правила проверяются раньше индекса. Выбирается первый сработавший уровень;
причины более низких уровней показываются как «дополнительно».

1. **Требуется экспертная проверка**
   - заводской номер или модель «расходится» между документом и фото — даже если
     сотрудник выбрал или ввёл значение (в отчёте показано, как разрешено);
   - аналогов нет или меньше N = 3 (диапазон не построен);
   - индекс ниже порога `routing_score_threshold` = 50.
2. **Запросить материалы у клиента** (с конкретным списком)
   - поле «не подтверждено» из-за качества фото → переснять конкретное фото;
   - ключевое поле есть только в документе → переснять шильдик;
   - паспорт неполный (нет ключевых полей) → дозагрузить полный паспорт;
   - документ не обработан (повреждён) → загрузить заново;
   - производитель или год «расходится» → уточнить у клиента. Этого правила не было
     в постановке; добавлено, чтобы такие расхождения не оставались без маршрута.
3. **Готово к проверке сотрудником** — если ничего не сработало.

Флаг «Техническое состояние и наработка не оценены» — информационный, на маршрут
не влияет. Ни один маршрут не означает одобрения: **система не принимает кредитное
решение** и не решает, принимать ли залог.

## Выбор параметров и ограничения

- Веса 20/30/30/20, баллы согласованности и аналогов выбраны экспертно, для
  демонстрации; не откалиброваны.
- Порог 50 — половина шкалы. При выборе весов уже были прикинуты баллы сценариев
  на синтетике (размытое фото ≈ 54), поэтому порог нельзя считать выбранным «вслепую»:
  размытый сценарий проходит его с запасом менее 4 баллов, и небольшое изменение весов
  переведёт его к эксперту.
- Индекс не учитывает, *какие* поля расходятся, — это делают жёсткие правила.
- Качество фото считается по всем фото одинаково: общий вид станка без шильдика с
  флагом качества снижает индекс так же, как размытый шильдик.
- Ограничения метрик качества фото — см. README, раздел «Ограничения».
