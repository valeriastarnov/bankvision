# Методика предварительной оценки по аналогам

> **Демонстрационная оценка на синтетических данных. Не является рыночной стоимостью.**
> База аналогов вымышленная (`data/analogs.csv`, `source = synthetic`), параметры —
> допущения для демонстрации алгоритма, а не рыночные данные.

Реализация: `app/services/valuation.py`. Параметры: `app/config.py`.

## Входные данные

Итоговые значения полей заявки после проверки сотрудником (экран проверки полей):
вид оборудования, модель, год выпуска, наибольший диаметр обработки, расстояние между
центрами (РМЦ). Поле, по которому сверка дала «расходится» или «не подтверждено» и
сотрудник ещё не выбрал значение, считается неизвестным.

## Подбор аналогов (три уровня)

1. **Точная модель.** Модель объекта и модель аналога совпадают после нормализации
   из `crosscheck.py`: регистр, кириллические/латинские двойники
   (А В Е К М Н О Р С Т Х), пробелы, дефисы. Так «TC-1640M» (латиница после OCR)
   находит записи «ТС-1640М» и «ТС 1640М». Нечёткое сравнение модели не применяется.
2. **Тот же класс.** Вид оборудования совпадает после нормализации, и обе
   характеристики в пределах допуска:
   `|D_аналога − D_объекта| ≤ δ_D · D_объекта`, `|L_аналога − L_объекта| ≤ δ_L · L_объекта`.
   Требует, чтобы у объекта были известны вид, D и L.
3. **Нет аналогов.**

Выбор уровня: если точных аналогов не меньше N — уровень «модель»; иначе, если по классу
не меньше N — «класс»; иначе используется найденное (модель, затем класс), но диапазон
не строится. Уровень показывается в результате.

## Поправка на возраст

```
k_i = (1 − d) ^ (год_аналога_i − год_объекта)
P_i' = P_i · k_i
```

Аналог новее объекта → `k < 1` (цена снижается), старше → `k > 1`.
Если год объекта неизвестен, поправка не делается (`k = 1`) и ставится флаг.
Скорректированная цена округляется до 1000 ₽.

## Итог

- Медиана скорректированных цен `P'`.
- Диапазон: P25–P75 (перцентили с линейной интерполяцией между упорядоченными
  значениями — метод numpy по умолчанию). Пример: для {100, 200, 300, 400}
  P25 = 175, медиана = 250, P75 = 325.
- Если аналогов меньше N — диапазон не строится, флаг «недостаточно аналогов».
- Для каждого аналога показываются: исходная цена, год, разница лет, коэффициент `k`,
  скорректированная цена, источник.

## Параметры (`app/config.py`)

| Параметр | Значение | Смысл |
|---|---|---|
| `valuation_annual_depreciation` (d) | 0.07 | **Демонстрационное допущение, не рыночные данные** |
| `valuation_min_analogs` (N) | 3 | Минимум аналогов для диапазона |
| `class_diameter_tolerance` (δ_D) | 0.10 | Допуск по диаметру обработки, ±10 % |
| `class_center_distance_tolerance` (δ_L) | 0.20 | Допуск по РМЦ, ±20 % |

Значения выбраны для демонстрации, не откалиброваны и не проверены на рынке.

## Флаги

- Всегда: «Техническое состояние и наработка не оценены: по фото и паспорту их
  определить нельзя».
- Недостаточно аналогов / нет аналогов.
- Год выпуска неизвестен — поправка на возраст не применялась.
- Аналоги по классу, а не по модели.
- Для подбора по классу не хватает данных объекта.

## Ограничения

- **Цены предложения ≠ цены сделок.** База имитирует объявления; реальная цена сделки
  обычно ниже и зависит от торга.
- **Нет поправок** на техническое состояние, наработку, ремонты, комплектацию
  (патроны, люнеты, УЦИ, оснастка), регион, срочность продажи, торг.
- Нет поправки на дату объявления (инфляция, изменение рынка во времени).
- Поправка на возраст — одна геометрическая формула с одним коэффициентом для всех
  моделей; реальная зависимость цены от возраста иная и не изучалась.
- Подбор по классу учитывает только вид, диаметр и РМЦ; мощность, точность, массу,
  наличие ЧПУ (кроме как через вид оборудования) — нет.
- База аналогов синтетическая и маленькая (34 записи); её цены порождены произвольной
  формулой (см. `data/analogs_README.md`), поэтому совпадение «оценки» с ценами базы
  ничего не говорит о точности на реальном рынке.
- Оценка — вспомогательная информация для сотрудника. Система не принимает кредитного
  решения и не решает, принимать ли залог.
