# BankVision — инструкция для Claude Code

## Проект
BankVision — интеллектуальная оценка залоговых активов. MVP для хакатона
«Финтех без границ: банк будущего для бизнеса и клиентов».
Дедлайн подачи заявки: 1 ноября 2026. Разработчик работает одна, ОС Windows, VS Code.

Сценарий: клиент загружает фото оборудования (токарный станок) и документ →
OCR и извлечение полей → ручная проверка полей сотрудником → сверка фото ↔ документ →
флаги расхождений и пропусков → подбор аналогов → предварительный диапазон стоимости →
индекс полноты и согласованности → отчёт → при сомнениях «требуется экспертная проверка».
AI не принимает кредитного решения и не решает, принимать ли залог.

## Правила честности (обязательны)
- Не выдумывать пользователей, интервью, статистику, рыночные данные, договорённости с банками.
- Реальных фото и документов нет. Все тестовые данные синтетические: генерируются скриптом
  `tests/generate_fixtures.py` и помечаются как синтетические в интерфейсе, README и отчёте.
- База аналогов (`data/analogs.csv`) синтетическая; у каждой записи поле `source`.
  В отчёте постоянная пометка: «Демонстрационная оценка, не является рыночной стоимостью».
- Индекс — «Индекс полноты и согласованности данных», правило-ориентированный балл.
  Не называть его вероятностью или откалиброванной уверенностью.
- Никаких заглушек распознавания без явной маркировки демо-режима в интерфейсе.
- Не сообщать «тест пройден» или «работает» без фактического запуска.
  Фактические результаты прогонов записывать в `tests/RESULTS.md` с датой.

## Стек
Python 3.11+, FastAPI, Jinja2 + немного JS, SQLite (sqlite3 стандартной библиотеки),
Tesseract OCR (rus+eng) через pytesseract, PyMuPDF, OpenCV, rapidfuzz, pandas, pytest.
Без платных API. Без React, без авторизации, без банковских интеграций.

Windows: путь к Tesseract задаётся в `app/config.py` через переменную окружения
`TESSERACT_CMD` (по умолчанию `C:\Program Files\Tesseract-OCR\tesseract.exe`).
Использовать `pathlib` для путей. Команды в README давать для PowerShell.

## Итерации и критерии готовности
Не переходить к следующей, пока не выполнен критерий текущей.
После каждой итерации: список изменённых файлов, что реализовано, какие проверки запущены
и с каким результатом, что осталось.

0. Каркас: FastAPI, SQLite, создание заявки, загрузка 1–5 фото (jpg/png) и документа
   (pdf/jpg/png), лимит размера. Критерий: файлы сохраняются; неверный формат отклоняется
   с понятным сообщением; pytest проходит.
1. PDF, OCR, качество фото. Текстовый слой PDF, при отсутствии — растеризация и OCR.
   Предобработка шильдика (grayscale, контраст, порог). Качество: размытость (дисперсия
   Лапласиана), яркость, разрешение; пороги в config. Критерий: на синтетике текст
   извлекается; размытое фото получает флаг и подсказку.
2. Извлечение полей (производитель, модель, серийный номер, год, характеристики) правилами;
   экран ручной правки с пометкой «исправлено вручную». Критерий: поля извлекаются
   на синтетике; правка сохраняется и попадает в журнал.
3. Cross-check: нормализация OCR-ошибок (O/0, I/1/l, S/5, B/8), rapidfuzz.
   Статусы: совпадает / расходится / нет в одном источнике / нет нигде.
   Критерий: тесты «совпадение», «расхождение», «нет серийного номера».
4. Оценка: отбор аналогов по типу и модели (затем по классу), поправка на возраст,
   медиана и разброс; методика в docs. При < N аналогов диапазон не строится, ставится флаг.
   Критерий: юнит-тесты формулы; сценарий «нет аналогов».
5. Индекс (компоненты: качество фото, полнота полей, согласованность, число аналогов;
   веса в config и docs), маршрутизация, HTML-отчёт (характеристики, основания оценки,
   ограничения, риски, пометка о синтетике), печать в PDF через браузер.
   Критерий: 7 сценариев ниже дают ожидаемый маршрут.
6. README (установка на Windows, запуск, проверка), Dockerfile, полный прогон тестов,
   `tests/RESULTS.md`.

## Обязательные тестовые сценарии
1. Корректные фото и полный документ.
2. Некачественные фото (размытие, темнота).
3. Отсутствует серийный номер.
4. Расхождение модели или номера между документом и фото шильдика.
5. Нет подходящих аналогов.
6. Ошибка обработки файла (битый PDF, неверный формат).
7. Недостаточная полнота данных.

Синтетические фикстуры: шильдики рисуются через Pillow (табличка с полями, шум, наклон,
опционально размытие), документы — простые PDF-паспорта оборудования.
Производители и модели вымышленные, без реальных реквизитов компаний.

## Приоритеты при нехватке времени
Сначала P0 (весь сценарий выше). Из P1 оставить только проверку качества фото
и журнал. Отложено: нейросетевое распознавание вида станка, геометрические признаки,
другие типы активов, авторизация, интеграции, парсинг реальных объявлений.
